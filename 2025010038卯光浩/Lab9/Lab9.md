## 二、阅读已完成的双向链表 list.h

### 2.1 真实节点与两个哨兵

Lab8 的 `Vector<T>` 使用一段连续的动态数组；本次 `List<T>` 使用逐个申请的节点，并通过前驱、后继指针连接。每个节点包含：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `pred` | 指向前驱节点的指针 |
| `succ` | 指向后继节点的指针 |

`ListNodePosi(T)` 是课本风格的宏，展开为 `ListNode<T>*`，表示节点位置。`Rank` 是 `int` 的别名，用于计数和窗口编号。

链表另设 `header`、`trailer` 两个哨兵，它们不保存有效队列元素，也不计入 `_size`：

```text
空表：        header <-> trailer                      size() == 0

插入元素后：  header <-> [10] <-> [20] <-> [30] <-> trailer
                         首个真实节点      最后真实节点   size() == 3
```

`header->pred` 和 `trailer->succ` 为 `nullptr`。**这是带双哨兵的双向链表，不是循环链表。** 空表也有两个哨兵；判空应看 `empty()`，不能看 `first()` 是否为 `nullptr`。

`_size`、`header`、`trailer` 位于 `List` 的 `private` 区域，只有链表自己管理它们。`Queue` 通过基类公有接口操作，不直接修改这些成员。

### 2.2 本实验提供的接口

| 接口 | 约定 |
| :--- | :--- |
| `List<T> L;` | 构造空表，创建并连接两个哨兵 |
| `size()` / `empty()` | 查询真实节点数、是否为空 |
| `first()` / `last()` | 返回首、尾真实节点的位置；空表时分别返回尾哨兵、头哨兵，不能据此读取有效元素 |
| `insertAsFirst(e)` | 在首部插入，返回新节点的位置 |
| `insertAsLast(e)` | 在尾部插入，返回新节点的位置 |
| `remove(p)` | 删除并返回节点 `p` 保存的元素；要求 `p` 是本表的真实节点 |
| `clear()` | 删除全部真实节点，返回删除个数，保留两个哨兵以便复用 |
| `~List()` | 清空真实节点，再释放两个哨兵 |

注意：`remove` 返回**被删元素**，`clear` 返回**删除个数**，两者含义不同。`remove` 不接受哨兵、空指针、其他链表的节点或已经删除的节点；调用者保证这些条件成立。

`ListNode` 的 `insertAsPred`、`insertAsSucc` 负责局部接链，`List` 的插入函数还负责更新 `_size`。学生不要绕过 `List` 直接调用节点插入函数，否则节点数与实际链条会不一致。链表析构时会自动释放节点，队列无需另写内存管理代码。

本版不包含查找、排序、去重与深拷贝；拷贝构造和赋值已通过 `= delete` 禁用，避免裸指针浅拷贝造成重复释放。`Queue<T>` 也不能复制，但可以用引用传递；`Queue<Customer> windows[3];` 是分别构造三个队列，不是在复制队列。元素须可默认构造、可复制，本实验使用 `int`、`char` 和 `Customer`。

## 三、从 List<T> 派生 Queue<T>

### 3.1 队列是对操作位置的限制

队列采用 **先进先出（FIFO）**：最先进入的元素最先离开。本实验将链表的**首端作为队首，末端作为队尾**。

依次入队 `10、20、30` 后，队首是 `10`，队尾是 `30`；出队一次返回 `10`，剩余顺序是 `20、30`。这与 Lab8 的栈在同一端进出不同。

类的声明已提供：

```cpp
template <typename T>
class Queue : public List<T> {
public:
    void enqueue(const T& e);
    T dequeue();
    T& front();
};
```

`public List<T>` 表示公有继承。基类负责构造、维护和释放链表；**不要再给 `Queue` 添加节点指针、计数器、构造函数或析构函数。**

与 Lab8 一样，公有继承不会自动隐藏基类的其他公有接口。本实验约定：循环分配器、银行模拟及队列测试只使用 `enqueue`、`dequeue`、`front`、`size`、`empty`；不能绕过队列接口直接操作节点。

### 3.2 三个函数的要求

| 函数 | 要求 |
| :--- | :--- |
| `enqueue(e)` | 复用基类的尾插接口，在队尾插入；不自己编写接链代码 |
| `dequeue()` | 复用基类的首节点访问、删除接口，返回被删元素的值；调用者保证非空 |
| `front()` | 返回首个真实节点的 `data` 引用，不删除节点、大小不变；调用者保证非空 |

调用者必须先确认队列非空，才能调用 `dequeue()` 或 `front()`。哨兵虽然也是节点，却不是可供出队的元素；删除哨兵会破坏链表。

`front` 返回引用，因此 `Q.front() = 15;` 会修改队内元素。删除队首后，该节点中的引用随即失效，不能继续使用；仅在队尾入队不会移动已有节点。循环分配器应保存出队返回的**值**再入队，不保存已删除节点的引用。

模板派生类中引用依赖于 `T` 的基类成员时，请显式写出 `this->` 或 `List<T>::`，例如 `this->size()`。仅写裸名字可能因模板名称查找规则而编译失败。`first()` 返回的是节点指针，不是元素值，注意节点与 `data` 的区别。

不得使用 `std::queue`、`std::deque`、`std::list`、`std::vector` 或其他容器代替自己的队列，也不得另外用数组或链表重新实现队列。保留模板、接口、返回类型和所有 `const`。模板函数体仍然放在 `queue.h`，不创建 `queue.cpp`。

## 四、队列应用一：循环分配器

### 4.1 课本思路：服务一次，再排到队尾

当若干对象需要轮流获得同一种服务时，可以将它们依次放入队列：**取出队首 → 为它服务一次 → 将它重新放到队尾**。这样各对象按原有顺序循环获得服务，不需要将底层链表改成首尾相连。

本实验用字符 `A、B、C` 表示三个对象，用输出字符表示一次服务。为了让演示可以结束，将教材持续进行的分配过程限制为最多 `rounds` 次。这里**一次分配只服务一个对象**，不是把所有对象都服务一遍；三个对象分配 8 次，不是服务 24 次。

本题没有对象永久离开，也没有新对象加入，不实现任务完成后退出、约瑟夫淘汰或完整的进程调度器。

### 4.2 学生任务

补全 `round_robin.cpp` 中的函数：


要求如下：

- `Q` 由调用者按初始顺序入队；通过引用传入，函数应改变原队列。
- 调用者保证 `rounds >= 0`；`rounds == 0` 时不服务、不改变队列。
- 每次分配前先判空；空队列立即结束，不访问队首或出队。
- 每次取出一个队首对象，使用 **`std::cout << e << ' ';`** 表示服务，然后重新入队。
- 不在函数中输出标题、换行或其他说明。教师测试代码会临时收集 `std::cout` 的输出，用于核对实际服务顺序；输出收集与恢复已写好，不要求学生实现或修改。

对非空队列，每次分配结束后，元素个数不变，刚获得服务的对象位于队尾。

## 五、队列应用二：银行服务模拟

### 5.1 顾客与窗口

```cpp
struct Customer {
    int window;
    unsigned int time;
};
```

`window` 是所属窗口编号，从 `0` 开始；`time` 是顾客尚需服务的时间，入队时大于 `0`。一个窗口对应一个 `Queue<Customer>`，队首正在接受服务，后面的顾客等待。`size()` 统计该窗口的全部顾客，包括正在服务的队首。

**`nWin` 是窗口总数**，名称来自 *number of windows*。`windows` 是保存各窗口顾客队列的数组：例如 `nWin = 3` 时，有 `windows[0]`、`windows[1]`、`windows[2]` 三个窗口，编号为 `0～2`。`Customer::window` 保存某位顾客所属的窗口编号，`windows[i].size()` 表示第 `i` 个窗口的顾客人数。

银行算法的核心是：**新顾客选择最短队列入队，各窗口只服务队首，完成服务的顾客出队。**

### 5.2 学生任务一：选择最短队列

补全：

```cpp
int bestWindow(Queue<Customer> windows[], Rank nWin);
```

参数 `windows` 是队列数组，`nWin` 是数组中的窗口总数，调用者保证 `nWin > 0`。比较各窗口的**队列人数**，返回最短队列的编号；同长时选编号最小的窗口。可以从窗口 `0` 开始，扫描其余窗口，仅发现更短队列时更新候选。

### 5.3 学生任务二：服务一个时间单位

补全：

```cpp
int serveOneTick(Queue<Customer> windows[], Rank nWin);
```

依次检查所有窗口：

1. 空队列跳过。
2. 非空队列通过 `front()` 将队首顾客的 `time` 减 `1`。
3. 减到 `0` 时，调用 `dequeue()` 让顾客离开，并增加完成计数。
4. 继续下一个窗口；刚成为队首的顾客要等到下一轮才能接受服务。

返回本轮完成服务的人数。要修改队内顾客，不能只给 `Customer c = Q.front();` 得到的副本减时间。

### 5.4 阅读模拟主流程

教师提供的 `simulate` 依次接收窗口总数 `nWin`、营业时长 `servTime` 和固定到达表 `arrivals`：

```cpp
void simulate(Rank nWin, Rank servTime, const unsigned int arrivals[]);
```

例如 `simulate(2, 6, arrivals)` 表示设置 **2 个窗口（编号 0、1）**，模拟 **6 个时间单位**。`arrivals[now]` 为本时刻新顾客所需的服务时间，`0` 表示无人到达。每轮按以下顺序执行：

1. **到达并入队**：调用 `bestWindow`，将新顾客加入所选窗口的队尾。
2. **服务并出队**：调用 `serveOneTick`，让每个非空窗口服务一次。
3. **观察结果**：输出本轮完成数、各窗口人数及队首剩余时间。

新顾客如果直接成为队首，本轮即可接受一个单位的服务。营业时长结束后停止模拟，统计剩余人数，再释放窗口数组。

### 5.5 运行固定场景

`main` 提供 **2 个窗口、6 个时间单位**，到达表为 `{3, 2, 4, 1, 2, 0}`。补全两个函数后运行 `lab9_bank`，输出应为：

```text

t=1 arrival=2 window=1 served=0 | W0 size=1 front=1 | W1 size=1 front=1
t=2 arrival=4 window=0 served=2 | W0 size=1 front=4 | W1 size=0 front=-
t=3 arrival=1 window=1 served=1 | W0 size=1 front=3 | W1 size=0 front=-
t=4 arrival=2 window=1 served=0 | W0 size=1 front=2 | W1 size=1 front=1
```

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留“填写”等占位文字。

### 6.1 链表与队列接口

| 队列操作 | 操作位置                       | 复用的 List 接口或节点成员 | 返回值的含义            |
| :--- |:-------------------------------|:---------------------------|:------------------------|
| `enqueue(e)` | 表尾（尾哨兵之前）             | insertAsLast(e)            | 新插入节点的指针        |
| `dequeue()` | 表头（头哨兵之后，首真是节点） | remove(first())            | 被删除节点中保存的元素T |
| `front()` | 表头（头哨兵之后，首真实节点） | first()->data              | 队首元素的引用T&        |

1. 空表的 `header`、`trailer` 如何连接？两个哨兵是否计入 `size()`？为什么第一次插入和删除唯一元素不需要另写一套接链逻辑？

   > 空表header与trailer互相指向。哨兵不计入size，size只统计真实节点。哨兵固定不变，增删只修改真实节点链接，无需额外逻辑。

2. `remove` 为什么先保存元素再删除节点？`clear` 与析构对哨兵的处理有何不同？为什么 `Queue` 不需要自己写 `new`、`delete`？

   > remove先存元素，删除节点后内存释放，无法读取data。
   clear删除全部真实节点，保留哨兵；析构函数才释放哨兵。
   Queue依靠List完成new/delete，不用自己管理内存。

3. `front()` 为什么返回引用，而 `dequeue()` 返回值？保存队首引用后，仅入队会使它失效吗？删除该队首后呢？

   > front返回引用，可读写队首元素；dequeue删除节点，不能返回引用，只能返回元素副本。
   出队后原节点释放，之前保存的队首引用失效

### 6.2 手工追踪循环分配器

初始队列为 `A、B、C`，进行 **5 次分配**。队列按“队首 → 队尾”填写。

| 分配次数 | 本次服务对象 | 出队后、重新入队前的队列 | 重新入队后的队列 |
| :---: |:------------:|:-------------------------|:-----------------|
| 1 |      A       | BC                       | BCA              |
| 2 |      B       | CA                       | CAB              |
| 3 |      C       | AB                       | ABC              |
| 4 |      A       | BC                       | BCA              |
| 5 |      B       | CA                        | CAB              |

- 五次分配中，每个对象分别获得几次服务？若再分配一次，下一个是谁？答：五次分配服务对象：A、B、C、A、B；再分配一次：C
- 为什么“循环分配器”不要求使用循环链表？若忘记将对象重新入队，会发生什么？答：循环分配器不需要循环链表：普通队列每次服务完把元素移到队尾即可，用普通单向/双向链表实现队列就够用。忘记重新入队：元素直接离开队列，不再参与后续调度。
- 如果一开始队列为空，为什么即使 `rounds > 0` 也应立即结束？答：队列为空时，即使rounds>0也要结束；没有顾客可以服务，无需继续循环

### 6.3 手工追踪银行服务

只有 **1 个窗口**，营业 **4 个时间单位**，到达表为 `{2, 1, 3, 0}`。三位顾客按到达顺序记作 A、B、C；用 `A:1` 表示顾客 A 还需 1 个单位服务。按“先到达，再服务”的顺序推演，无需修改程序。

| `now` | 本时刻到达 | 本轮服务结束后的队列（队首 → 队尾） | 本轮离开的顾客 |
| :---: | :--- |:------------------------------------|:---------------|
| 0 | A，需要 2 单位 | A:1                                 | 无             |
| 1 | B，需要 1 单位 | A:0,B:1                             | A              |
| 2 | C，需要 3 单位 | B:0,C:3                             | B              |
| 3 | 无 | C:2                                 | 无             |

- 最终统计：`arrived =`3，`served =`2，`remaining =`1。
- `now == 1` 时 A 离开后，为什么 B 不能在同一轮完成服务？答：now=1时A刚好本轮结束离开，B是本时刻才到达；一轮内先完成上一个顾客服务，新到达顾客只能在下一轮开始服务，因此B不能同一轮服务

### 6.4 时间与空间

按本实验实现分析；视元素复制与单个节点申请、释放为常数开销。令 `n` 为队列元素数，`k` 为实际完成的分配次数，`w` 为窗口数，`t` 为模拟时间单位数，`m` 为模拟中同时在队的顾客总数的最大值。

| 项目 | 复杂度 | 简要理由                                            |
| :--- |:-------|:----------------------------------------------------|
| `enqueue()`、`dequeue()`、`front()` 各自的时间 | O(1)   | 头尾插入删除、读取队首，都是固定次数操作，不随n变化 |
| 一个有 `n` 个元素的队列占用的空间（含哨兵） | O(n)   | n各数据节点+2个哨兵，节点数量随元素个数线性增长     |
| 非空队列完成 `k` 次循环分配的总时间 | O(k)   | 每次服务出+入队都是O（1）,一共k次操作               |
| `roundRobin` 除已有队列、输出记录外的辅助空间 | O(1)   | 之使用少量临时变量，额外空间不随输入规模变化        |
| `bestWindow` 的时间 | O(w)   | 遍历全部w个窗口，循环次数等于窗口个数               |
| `serveOneTick` 的时间 | O(1)   | 只处理队首操作，固定操作，与队列长度无关            |
| 银行模拟 `t` 个时间单位的主循环总时间（忽略输出成本） | O(t)   | 每时间单位一轮循环，循环t次                         |
| 银行窗口数组与全部队列的峰值空间 | O(m)   | m为最大同时排队人数，节点数量随排队人数线性增长     |

说明：哨兵使空队列仍占常数空间；空间表达式需能解释 `n == 0`、`m == 0` 的情况。银行主循环逐轮扫描窗口，初始化与最后析构不计入“主循环总时间”。

### 6.5 两个应用的联系与区别

用自己的话回答，每题两三句话。

1. 循环分配器和银行模拟分别在何时出队？出队后是否重新入队？为什么二者都适合使用 FIFO 队列？

   > 循环分配器：每次服务完成就出队，然后重新入队；银行模拟：顾客服务完成后出队，不再入队。二者都遵循先来先服务的规则，FIFO队列天然匹配这种顺序调度需求。

2. 银行程序中的 `Customer c = Q.front();` 与直接通过 `Q.front().time` 修改元素有什么区别？只给局部变量 `c.time` 减 1，会导致什么现象？

   > 2.Customer c = Q.front(); 是拷贝一份新的局部变量，修改c.time不会改动队列里原始顾客数据。
   Q.front().time -=1 直接操作队首元素的引用，会修改队列中保存的真实顾客剩余服务时间。

3. 最短队列是否一定让新顾客等待时间最短？请举一个队列人数与服务时间不同的例子。为什么本次仍按人数选择？

   > 最短队列不一定让等待时间最短。
   例子：窗口1队列1人（需要10分钟），窗口2队列2人（每人1分钟）。新顾客选人数少的窗口1，等待更久。
   本次仍按人数选：题目策略是仅按排队人数分配顾客，不预估服务时长。
