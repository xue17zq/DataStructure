## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 不递归，顺序执行三步 | 不输出，只 new、赋 `data`、连 `lc`/`rc` | 6 个局部指针变量（`A`～`F`），无容器 |
| `preorder()` | `root == nullptr` 直接返回 | 进入函数后、两次递归**之前** | 系统递归栈 |
| `inorder()` | `root == nullptr` 直接返回 | 左子树递归之后、右子树递归**之前** | 系统递归栈 |
| `postorder()` | `root == nullptr` 直接返回 | 两次递归**之后** | 系统递归栈 |
| `levelOrder()` | `root == nullptr` 直接返回；循环靠队列非空维持 | 节点**出队后**立即输出 | `std::queue<Node*>` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 因为三者共用同一个骨架：先判空返回，再对左、右子树各递归一次；二叉树的结构决定了只有"访问根"这一件事能与两次递归排列组合，位置不同就得到不同口诀。若去掉访问语句，三个函数就完全一样了——都只是无输出地把整棵树走一遍，彼此再无区别（只剩递归框架，什么也不产生）。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 置空保证每个 `new` 出来的节点在未指定孩子前就是一个干净的叶子：没连上的位置一律是 `nullptr`，绝不会指向野地址，叶子判断也可靠。若孩子指针是随机值，遍历会沿着根本不存在的"边"走进非法内存，可能直接崩溃或输出乱码；`destroyTree` 还会去释放本不属于它的地址，造成未定义行为甚至堆损坏。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 这对应**后序遍历**（左、右、根）：必须等两棵子树都释放完才轮到根，因为释放根之前还要靠根的 `lc`、`rc` 找到子树。若先 `delete` 根，根的内存立刻回收，接着再读 `root->lc`、`root->rc` 就是使用已释放的内存（悬垂指针），行为未定义，可能崩溃，也可能据此释放到错误地址或漏掉整棵子树造成内存泄漏。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | `Θ(n)` | 每个节点恰好被访问一次，一次输出为常数，故 `n × Θ(1)`。 |
| 三种递归遍历各自的辅助空间（递归栈） | `Θ(h)` | 每层递归压入一帧，深度由树高决定；空树 `h = 0` 不占栈，单节点 `h = 1` 占 1 帧。 |
| 层次遍历的时间 | `Θ(n)` | 每个节点入队、出队、输出各一次，均摊常数，共 `n` 个节点。 |
| 层次遍历的辅助空间（队列） | `Θ(w)` | 队列中同时存在的最多是某一层的节点，峰值为最大宽度 `w`；空树为 0，单节点为 1。 |
| `main` 中手动创建 6 个节点的时间 | `Θ(1)` | 固定 6 次 `new` 与固定次数的赋值、连指针，与树规模无关，是常数次操作。 |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。

递归深度达到 `n` 的是**单支斜树**（每个节点只有一个孩子，如向左或向右的单链），此时 `h = n`，递归栈压满 `n` 帧；队列长度达到 `n` 阶的是**接近满的完全二叉树**，遍历到最后一层时，上一层尚未出队的节点与新入队的孩子同时留在队中，峰值宽度与 `n` 同阶（最宽一层可达 `Θ(n)`）。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归之后得到**后序遍历**（左、右、根）；移到中间（先递归左子树，再访问根，最后递归右子树）得到**中序遍历**（左、根、右）。可见三种递归遍历的差别只是访问根这一行的位置。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求"先入队的上层节点先出队"，出队后才把孩子排到队尾，FIFO 正好保证按层、层内从左到右的顺序。换成栈是 LIFO，后入的孩子先出，输出会变成深度优先的走向——先沿左链一路走到底，同层节点不再相邻，序列退化成类似先序（若压栈时先右后左）的形状，失去"按层"的含义。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当树高不超过 2 时二者必然相同，例如单节点树 `A`，或两层的 `A(B, C)`：先序与层次都是 `A B C`。退化的单链也相同，例如左单链 `A-B-C`，先序 `A B C`、层次 `A B C`。一旦某节点有孩子且同层还有别的节点的子树，先序会先钻进左子树深处，与层次遍历分道扬镳，例如满三层树先序 `A B D E C F G`、层次 `A B C D E F G`。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 能。先序的第一个是根，到中序里把序列切成左右两半，再对两侧递归即可唯一确定。例如先序 `A B D C`、中序 `D B A C`：`A` 为根，中序左侧 `D B` 是左子树、右侧 `C` 是右子树，继续递归唯一推出整棵树。只给先序不行，因为分不清每个孩子的左右：先序 `A B C` 至少对应 `A` 的左孩子是 `B`、右孩子是 `C`，以及左单链 `A-B` 且 `B` 右孩子为 `C` 等多棵树。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 本例共写了 6 行 `new`、6 行 `data` 赋值、14 行 `lc`/`rc` 连接和 1 行 `root = A`，约 27 行。1000 个节点要写几千行，既繁琐又极易连错，完全不现实。同样的元素组织成不同形状的树查找代价不同，下一阶段应学习**二叉搜索树（二叉排序树）**：按比较规则决定每个新元素的落点，让树尽量"矮胖"，使查找、插入都在树高范围内完成（必要时再学 AVL、红黑树等平衡结构）。
