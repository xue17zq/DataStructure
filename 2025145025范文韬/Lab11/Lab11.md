## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 非递归，无出口；前提是先 new 出节点再赋值、连边 | 建树阶段本身不输出任何内容，输出由后续遍历完成 | 无，仅使用裸指针 A~F 与根指针 root |
| `preorder()` | `root == nullptr` 时直接 `return` | 进入函数后、递归左右子树**之前**（先访问根） | 系统递归调用栈 |
| `inorder()` | `root == nullptr` 时直接 `return` | 递归完左子树**之后**、递归右子树**之前** | 系统递归调用栈 |
| `postorder()` | `root == nullptr` 时直接 `return` | 递归完左右子树**之后**（最后访问根） | 系统递归调用栈 |
| `levelOrder()` | 前提 `root == nullptr` 时直接 `return`；循环前提为队列非空 | 每次队头节点**出队时**输出 | `std::queue<Node*>` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种递归遍历的控制结构完全相同：都有一个空树出口、一句"访问根"、对左右子树的两次递归调用，唯一不同是"访问根 `std::cout << root->data`"这一句相对两次递归摆放的位置，而这恰恰决定了根节点在输出序列中出现的位置（最前=先序、中间=中序、最后=后序）。如果把这句访问语句去掉，三个函数都只剩"空树返回 + 两次空转递归"，不再产生任何输出，彼此完全等价，再也无法区分。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 置空使每个新建节点一诞生就是合法的叶子：建树时只需给真实存在的父子边赋值，凡是没赋值的指针保持 `nullptr`，就表示"该方向没有孩子"，正好充当遍历和释放的终止信号。若两个孩子是随机野值，四种遍历会顺着野指针访问非法内存：空树出口判 `nullptr` 永远不成立，递归/循环无法终止，必然读出乱码或直接段错误崩溃；`destroyTree` 也会去 `delete` 野指针造成二次破坏。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 这与**后序遍历**（左-右-根）的顺序一致。必须先释放孩子，再释放父节点：因为父节点的指针域 `lc`、`rc` 保存着子树地址，是进入子树的唯一入口，父节点一旦先被释放，再去访问 `root->lc`、`root->rc` 就是对已释放对象取成员（use-after-free，释放后使用），属未定义行为，通常导致崩溃或内存破坏。反过来"先子后根"在 `delete root` 之前已经把两条边用完了，安全。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序遵循"左-根-右"，要访问任何根都必须先把它的整棵左子树处理完，于是会一路沿 `lc` 下降到最左端。从根 `A` 出发：`A->lc` 到 `B`，再 `B->lc` 到 `D`；`D` 的 `lc` 为空，递归到空树直接返回，`D` 成为第一个被访问输出的节点。所以中序第一个节点就是从根反复走 `lc` 指针能到达的最左叶子 `D`。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左单链：中序与后序相同（都是 `C B A`）。原因：每个节点只有左孩子、没有右孩子，"左-根"（中序）与"左-根"在忽略空右子树后等价，且都没有"右"参与，于是中序 `左,根` 与后序 `左,根` 退化为同一顺序，逐层递归展开即 `C B A`；先序则为 `A B C`，与之不同。向右单链：先序与中序相同（都是 `A B C`）。原因：每个节点只有右孩子，先序"根,右"与中序"根,右"在忽略空左子树后一致，逐层展开即 `A B C`；后序则退化为 `C B A`。

3. 满二叉树的手工推演与课堂演示 `BinTreeTraversal.cpp` 的输出是否一致？指定树的推演与自己程序的输出是否一致？如有出入，错在哪里？

   > 一致。满二叉树手推的先序 `A B D E C F G`、中序 `D B E A F C G`、后序 `D E B F G C A`、层次 `A B C D E F G` 与课堂演示输出相同；指定树手推的先序 `A B D E C F`、中序 `D B E A C F`、后序 `D E B F C A`、层次 `A B C D E F` 与本程序实际输出逐行一致，无出入。关键在 `C` 没有左孩子：中序里 `C` 之前不再出现它的左子树，先序/层次里 `F` 是 `C` 的右孩子，按规则正确排出。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | O(n) | 每个节点恰好被访问输出一次，每节点对应的函数调用为常数开销，共 O(n) |
| 三种递归遍历各自的辅助空间（递归栈） | O(h)，最坏 O(n) | 任意时刻递归深度不超过树高 h；树退化为单链时 h = n |
| 层次遍历的时间 | O(n) | 每个节点入队、出队各一次，单次为常数开销，合计 O(n) |
| 层次遍历的辅助空间（队列） | O(w)，最坏 O(n) | 队列同时容纳的节点数不超过约一层的宽度，峰值即最大宽度 w |
| `main` 中手动创建 6 个节点的时间 | O(1) | 固定 6 个节点，new、赋 data、连 lc/rc 都是常数条语句，与 n 无关 |

说明：递归辅助空间在空树时为 O(1)（仅一层栈帧、立即返回），单节点树为 O(1)~O(2)；当树每层只有一个孩子、退化成**单链**时树高 h = n，递归深度达到 n。队列辅助空间在空树时为 O(1)（不入队），单节点树时为 1；当**最大宽度 w = n** 时队列长度达到 n——这种"最宽"出现在所有内部节点都只有一个孩子的极端之外的对称情形不成立，真正让 w 趋近 n 的是节点尽量铺在同一层，例如根节点带 n-1 个孩子的一层"星形"树，其第二层宽度 n-1，队列峰值约为 n-1 ≈ n。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归之后即"左、右、根"，得到**后序遍历**；移到两次递归中间即"左、根、右"，得到**中序遍历**。可见三种递归遍历就是"访问根"这一句在左递归与右递归三种位置（前、中、后）的三种排布。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求"先发现的先处理"：同层节点必须按从左到右被依次访问，且整层访问完才轮到下一层，这正是先进先出队列的性质。换成栈（后进先出）后，访问顺序不再逐层推进：以"先压左、再压右"为例，出栈会先取到右孩子，得到的是"根→右→左"的**深度优先**式遍历（先序的左右镜像），靠近根的右支会抢先于同层左支之后的更深层节点，完全失去了"从上到下、同层从左到右"的层次特征。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当树"每个内部节点最多只有一个左孩子、没有右孩子"时两者相同。最简例子：单节点树 `A`，先序 = 层次 = `A`。再如向左单链 `A-B-C`：先序 `A B C`，层次逐层也是 `A B C`，二者相同。反之，一旦有节点带右孩子，二者就不同——例如本作业的指定树，先序 `A B D E C F` 把 `B` 的整棵子树排在 `C` 之前，而层次 `A B C D E F` 把 `C` 排在第二层先于 `D、E`，顺序不同。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 先序+中序可以唯一确定。例：先序 `A B D C`、中序 `D B A C`。先序首元素 `A` 是根；在中序中 `A` 把序列分成左 `{D B}`（属左子树）和右 `{C}`（属右子树）；左子树的先序段是 `B D`，其首元素 `B` 是左子树根，中序中 `B` 左边 `{D}` 即 `B` 的左孩子；右子树根为 `C`。逐层递归可唯一还原整棵树。只给先序不能确定：先序 `A B` 既可能是 `A` 只有左孩子 `B`，也可能是 `A` 只有右孩子 `B`，两者先序相同但树形不同，无法区分。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 6 个节点写了约 18 行：6 行 `new`、6 行 `data` 赋值、6 行（12 个赋值）连接 `lc/rc`。若换成 1000 个节点就要写数千行且极易连错指针，完全不现实，也无法从无序元素自动生成。猜想下一阶段会学习**二叉搜索树（BST）**——它按"左小右大"规则在插入时自动定位位置，无需手工指定结构，建树与查找都能借助树高达到高效；并进一步引出**平衡二叉树（如 AVL）**来抑制单链退化、保证树高为对数级，从而让查找稳定地快。
