## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无递归出口；前提是逐个小 `new` 出 6 个节点 | 建树过程不访问、不输出任何字符 | 只用 6 个 `Node*` 局部变量，无其他结构 |
| `preorder()` | `root == nullptr` 直接返回 | 进入函数后**立即**输出根，再递归左、右子树 | 递归调用栈，深度为 `h + 1` |
| `inorder()` | `root == nullptr` 直接返回 | 先递归左子树，**回来之后**输出根，再递归右子树 | 递归调用栈，深度为 `h + 1` |
| `postorder()` | `root == nullptr` 直接返回 | 先递归左、右子树，**两者都回来之后**输出根 | 递归调用栈，深度为 `h + 1` |
| `levelOrder()` | `root == nullptr` 直接返回 | 出队时输出该节点，随后把它的左、右孩子入队 | `std::queue<Node*>`，最多装一层节点，`O(w)` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 因为三种遍历访问的节点集合与顺序（先左子树、后右子树）完全一样，唯一的差别就是"根"在这条时间线上排在哪个位置：先序在两次递归之前、中序在两者中间、后序在两者之后。若把输出那一句去掉，三个函数的递归调用顺序完全相同（都是先 `lc` 再 `rc`），函数体彻底一样，区别只剩下名字。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 默认构造函数把两个孩子置空，使每个新节点从一诞生就是"叶子"，因此只需显式连接真正有孩子的那些指针，没连的位置自然表示"这里没有子树"，遍历的递归出口 `root == nullptr` 才能可靠地停下来。若孩子是随机值，遍历会把野指针当成真实节点继续递归，输出乱码字符，甚至越过非法地址直接崩溃。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 必须先释放子树、最后释放根，因为根节点里保存着指向两棵子树的 `lc`、`rc`；一旦根先被 `delete`，就无法再找到子树，整片子树都成了泄漏。这个"左—右—根"的顺序正好对应**后序遍历**。若先 `delete` 根再递归释放子树，本质上是拿已被释放的内存里的指针去访问子树，属于悬空指针解引用，是未定义行为，多数情况下直接崩溃。

### 6.2 手工追踪四种遍历

对课堂演示的满二叉树（`A` 的左、右孩子是 `B`、`C`；`B` 的左、右孩子是 `D`、`E`；`C` 的左、右孩子是 `F`、`G`），**不看程序输出**，在草稿纸上推演后填写各序列（字符间用空格分隔）：

| 遍历 | 序列 |
| :--- | :--- |
| 先序 | A B D E C F G |
| 中序 | D B E A F C G |
| 后序 | D E B F G C A |
| 层次 | A B C D E F G |

再对本次作业指定的树（`C` 只有右孩子 `F`，共 6 个节点）推演四种序列，与 5.3 的程序输出对照。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序是"左—根—右"，只有在左子树被完全处理完之后才轮到根，所以第一个被访问的一定是整棵树中最靠左的那个节点。从根 `A` 出发，先沿 `A->lc` 走到 `B`，再沿 `B->lc` 走到 `D`；`D` 没有左孩子，于是它自己就是最左节点，第一个被输出。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左的单链树中，**先序**与**中序**序列相同，都是 `A B C`：每个节点只有左孩子，先序"根—左—右"输出根后一路向左，中序"左—根—右"先递归到最左的 `C` 再逐层回溯输出，两者恰好都得到自上而下的顺序；后序是 `C B A`，与它们不同。向右的单链树中，**先序**与**后序**相同，都是 `A B C`：先序输出根后一路向右，后序先递归到最右的 `C` 再回溯，也是自上而下的顺序；而中序会因为先递归左（空）再输出，得到的仍是 `A B C`，所以这棵树上三种遍历其实都相同。

3. 满二叉树的手工推演与课堂演示 `BinTreeTraversal.cpp` 的输出是否一致？指定树的推演与自己程序的输出是否一致？如有出入，错在哪里？

   > 一致：满二叉树的先序 `A B D E C F G`、中序 `D B E A F C G`、后序 `D E B F G C A`、层次 `A B C D E F G` 与按"根—左—右"等规则逐步推演的结果相同。指定树同样一致：程序输出先序 `A B D E C F`、中序 `D B E A C F`、后序 `D E B F C A`、层次 `A B C D E F`，与手工推演的四个序列逐位相符，没有出入。

### 6.3 手工展开递归调用

对只有三个节点的树 `A`（左孩子 `B`、右孩子 `C`）执行 `preorder(A)`。前两次调用已填好作示范，完成全表（空树调用也是一行）：

| 调用顺序 | 当前调用 | 动作 |
| :---: | :--- | :--- |
| 1 | `preorder(A)` | 输出 `A`，进入左子树 |
| 2 | `preorder(B)` | 输出 `B`，进入左子树 |
| 3 | `preorder(nullptr)`（`B` 的左空子树） | 是空树，直接返回，回到 `preorder(B)` |
| 4 | `preorder(nullptr)`（`B` 的右空子树） | 是空树，直接返回，`preorder(B)` 结束，回到 `preorder(A)` |
| 5 | `preorder(C)` | 输出 `C`，进入左子树 |
| 6 | `preorder(nullptr)`（`C` 的左空子树） | 是空树，直接返回，回到 `preorder(C)` |
| 7 | `preorder(nullptr)`（`C` 的右空子树） | 是空树，直接返回，`preorder(C)` 结束，整趟遍历结束 |

- 这 7 次调用中有几次是"空树直接返回"？4 次，分别对应第 3、4、6、7 行的四次空树调用。
- 对有 `n` 个节点的二叉树执行一次先序遍历，`preorder` 一共被调用多少次（含空树调用）？`2n + 1` 次。每个真实节点调用一次共 `n` 次，每个节点有左右两个指针槽，共 `2n` 个指针，其中 `n - 1` 个指向真实子节点、`n + 1` 个为空，所以空树调用 `n + 1` 次，合计 `n + (n + 1) = 2n + 1` 次。三节点树 `n = 3` 时为 7 次，与上表一致。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | `Θ(n)` | 每个节点恰好被访问（输出）一次，每次调用只做常数次操作，共 `O(n)` 次调用 |
| 三种递归遍历各自的辅助空间（递归栈） | `O(h)`，最坏 `Θ(n)` | 递归深度等于树高加一；空树、单节点树时树高为常数，仍只占常数栈空间 |
| 层次遍历的时间 | `Θ(n)` | 每个节点入队、出队、输出各一次，指针操作均为常数时间 |
| 层次遍历的辅助空间（队列） | `O(w)`，最坏 `Θ(n)` | 队列最多同时存放一层节点，即最大宽度 `w`；空树时队列为空，仍是常数 |
| `main` 中手动创建 6 个节点的时间 | `Θ(1)`（`O(n)`） | 6 次 `new`、6 次赋值、12 次指针赋值，都是常数条语句，与输入规模无关 |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。空树时三种递归遍历在第一次调用就返回，栈深为 1；单节点树栈深为 2，都只占常数空间，`O(h)` 在 `h = 1` 时即常数，`O(w)` 在 `w = 1` 时也是常数。**退化成单链的树**（每个节点最多一个孩子）会让递归深度达到 `n`，此时栈空间为 `Θ(n)`；**完全二叉树的最底一层**（或任何"宽而浅"的形状，例如根带 `n - 1` 个孩子的极端情况）会让某一层的节点数接近 `n`，队列长度达到 `n`。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归**之后**，就是"左—右—根"，即**后序遍历**。移到两次递归**中间**（先递归左子树、再输出根、最后递归右子树），就是"左—根—右"，即**中序遍历**。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 因为"从上到下、从左到右"要求先发现的孩子先被访问，正是先进先出：第 `k` 层的节点全部出队之后，第 `k+1` 层才依次到达队头，层次的先后自然被队列的顺序维持住。若换成栈（后进先出），刚入队的右孩子会抢在左孩子与同层其他节点之前被访问，输出不再逐层推进，而是变成一条"先深入右子树"的锯齿状顺序，本质上退化成深度优先一类的遍历，不再是层次遍历。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当先序顺序恰好与"逐层从左到右"的顺序一致时两者相同，最典型的是**向右的单链树**（`A` 的右孩子是 `B`，`B` 的右孩子是 `C`）：先序是 `A B C`，层次也是 `A B C`。反过来，**只有三个节点的满二叉树**（根 `A`，左 `B`、右 `C`）两者也相同，都是 `A B C`；但只要出现"某个节点的左孩子下面还有孩子"，先序会先钻下去，而层次会先访问同层的兄弟，两者就不同了，例如指定树中先序是 `A B D E C F`，层次是 `A B C D E F`。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 先序 + 中序可以唯一确定：先序的第一个元素必是根，在中序中找到它，就把中序切成左、右两段，两段长度也同样切分先序，再对两段递归即可。例如先序 `A B D E C F`、中序 `D B E A C F`，根 `A` 把中序切成 `D B E` 与 `C F`，于是 `A` 的左子树含 3 个节点、右子树含 2 个，继续递归就能唯一还原。只给先序则不能：先序 `A B` 既可能是"`B` 是 `A` 的左孩子"，也可能是"`B` 是 `A` 的右孩子"，两种树先序都是 `A B`，无法区分。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 6 个节点写了 6 行 `new`、6 行 `data` 赋值、12 行 `lc` / `rc` 连接，共 24 行，平均每个节点 4 行。1000 个节点就要约 4000 行，而且节点的地址、父子关系全靠手写，改一处就要连带改多处，显然不现实，也无法从数据（例如一个序列）自动生成树。同样的元素组织成不同形状，查找代价差别很大：退化成单链时要比较 `n` 次，而"左小右大"的树每层能排除一半，只要 `O(h)`；所以下一阶段应当学习**能按规则自动建树并支持有序查找的二叉排序树（及保持平衡的 AVL 树、红黑树）**，这样建树和查找才会高效。
