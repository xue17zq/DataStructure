## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


要求如下：

- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无递归出口；前提是每个 `new Node` 都返回非空指针 | 建树阶段不输出任何内容，连好指针后让 `root` 指向 `A` | 不需要辅助结构，只用 6 个局部指针 |
| `preorder()` | `root == nullptr` 直接返回 | 进入函数后立即输出根，再递归左右子树 | 递归栈，深度等于树高 |
| `inorder()` | `root == nullptr` 直接返回 | 递归完左子树后输出根，再递归右子树 | 递归栈，深度等于树高 |
| `postorder()` | `root == nullptr` 直接返回 | 两次递归都返回后才输出根 | 递归栈，深度等于树高 |
| `levelOrder()` | `root == nullptr` 直接返回；循环前提是队列非空 | 队头出队时输出该节点，随后把存在的左、右孩子依次入队 | `std::queue<Node*>` 先进先出队列 |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种递归遍历的框架完全相同：判空出口、遍历左子树、遍历右子树，差别只在“输出根”这一句放在两次递归的哪个位置。去掉这句后，三个函数体一模一样，只剩函数名不同，都退化为“把整棵树走一遍却不做任何事”。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 默认构造把 `lc`、`rc` 置空，使“没有孩子”这一状态天然成立：叶子不必逐个手工赋空，漏连的指针也不会变成野指针。若 `new` 出来的孩子是随机值，递归会顺着垃圾地址继续访问，属于未定义行为——常见表现是段错误崩溃、输出乱码，甚至无限递归。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > `destroyTree` 先递归释放左右子树、最后 `delete` 根，与后序遍历（左-右-根）一致。必须等子树释放完才能安全删除根；若先 `delete` 根，`root->lc`、`root->rc` 指向的子树就再也找不到了，必然内存泄漏，而且此时再访问这些指针是访问已释放内存，属于未定义行为。

### 6.2 手工追踪四种遍历

对课堂演示的满二叉树（`A` 的左、右孩子是 `B`、`C`；`B` 的左、右孩子是 `D`、`E`；`C` 的左、右孩子是 `F`、`G`），**不看程序输出**，在草稿纸上推演后填写各序列（字符间用空格分隔）：

| 遍历 | 序列 |
| :--- | :--- |
| 先序 | A B D E C F G |
| 中序 | D B E A F C G |
| 后序 | D E B F G C A |
| 层次 | A B C D E F G |

再对本次作业指定的树（`C` 只有右孩子 `F`，共 6 个节点）推演四种序列，与 5.3 的程序输出对照。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序是“左-根-右”，进入 `A` 后先不输出，沿 `A->lc` 下到 `B`，再沿 `B->lc` 下到 `D`；`D` 没有左孩子，于是最先输出 `D`。也就是说，中序序列的第一个节点就是整棵树“最左下”的节点。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左的单链树（`A->lc=B`、`B->lc=C`）：中序与后序相同，都是 `C B A`（先序为 `A B C`）。因为每层的右子树都为空，中序“左-根-右”与后序“左-右-根”在右子树为空时执行顺序完全重合。向右的单链树（`A->rc=B`、`B->rc=C`）：先序与中序相同，都是 `A B C`；因为每层左子树都为空，先序“根-左-右”与中序“左-根-右”在左子树为空时一致。

3. 满二叉树的手工推演与课堂演示 `BinTreeTraversal.cpp` 的输出是否一致？指定树的推演与自己程序的输出是否一致？如有出入，错在哪里？

   > 一致。满二叉树的手工推演 `A B D E C F G` 等与课堂演示 `BinTreeTraversal.cpp` 的输出相同；指定树（`C` 只有右孩子 `F`）的推演结果为 `A B D E C F`、`D B E A C F`、`D E B F C A`、`A B C D E F`，与本人程序的输出逐字符一致，没有出入。

### 6.3 手工展开递归调用

对只有三个节点的树 `A`（左孩子 `B`、右孩子 `C`）执行 `preorder(A)`。前两次调用已填好作示范，完成全表（空树调用也是一行）：

| 调用顺序 | 当前调用 | 动作 |
| :---: | :--- | :--- |
| 1 | `preorder(A)` | 输出 `A`，进入左子树 |
| 2 | `preorder(B)` | 输出 `B`，进入左子树 |
| 3 | `preorder(nullptr)` | `B` 的左子树为空，判空后直接返回 |
| 4 | `preorder(nullptr)` | `B` 的右子树为空，判空后返回，`preorder(B)` 结束，回到 `A` |
| 5 | `preorder(C)` | 输出 `C`，进入左子树 |
| 6 | `preorder(nullptr)` | `C` 的左子树为空，直接返回 |
| 7 | `preorder(nullptr)` | `C` 的右子树为空，直接返回，`preorder(C)` 结束，整次遍历结束 |

- 这 7 次调用中有几次是"空树直接返回"？4 次，即第 3、4、6、7 次调用，数量为 `n+1`。
- 对有 `n` 个节点的二叉树执行一次先序遍历，`preorder` 一共被调用多少次（含空树调用）？`2n+1` 次：`n` 次对非空节点的调用，加 `n+1` 次对空子树的调用。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | O(n) | 每个节点恰好被访问一次，输出为常数开销 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h)，最坏 O(n) | 递归栈深度等于树高 h；单链树退化为 n |
| 层次遍历的时间 | O(n) | 每个节点入队、出队各一次，均为常数开销 |
| 层次遍历的辅助空间（队列） | O(w)，最坏 O(n) | 队列中最多同时存放一层节点，峰值等于最大宽度 w |
| `main` 中手动创建 6 个节点的时间 | O(1)，常数 | 固定 6 个节点，语句条数不随 n 变化 |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。空树时 h = 0、w = 0，O(h)、O(w) 都退化为 O(1)，不额外占用空间；单节点树 h = w = 1。左（或右）单链树每层只有一个节点，树高 h = n，递归深度也随之达到 n；完全二叉树最后一层节点数最多，最大宽度 w 可达约 n/2，是队列峰值最大的常见形状。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 把“访问根”移到两次递归之后得到后序遍历（左-右-根）；移到两次递归中间得到中序遍历（左-根-右）。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 队列先进先出，才能保证同一层的节点按“先左后右”的入队顺序出队，从而逐层推进。换成栈是后进先出，会优先深入某一侧子树，输出变成深度优先（形似先序，且右子树先被处理），不再具备“按层”的性质。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当整棵树是一条单链（每个节点至多一个孩子）时两者相同。例如右链 `A->rc=B`、`B->rc=C`：先序是 `A B C`，层次也是 `A B C`；左链 `A->lc=B`、`B->lc=C` 同样都是 `A B C`。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 先序与中序可以唯一确定：例如先序 `A B D E C F G` 与中序 `D B E A F C G` 只能还原出本实验这棵满二叉树——先序第一个是根，用它把中序切成左右两段，再对两段递归。只给先序不能唯一确定：先序 `A B C` 至少对应 5 种不同形状的二叉树（`A(B(C))`、`A(B,C)` 及各类左右变体），根确定后无法判断后续节点挂在左侧还是右侧。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 6 个节点写了约 18 行（每个节点一句 `new`、一句赋 `data`、一到两句连指针）。1000 个节点的树显然不能用这种办法：代码量随节点数线性增长，既写不完也改不动。同样的元素，若都挂在一条链上，查找要逐个比较、退化为 O(n)；若树形较“矮”，沿分支下降只需 O(log n)。可以猜想，下一阶段会学习支持自动建树与高效查找的结构——`BinTree` 类模板（先序扩展序列建树）、二叉搜索树与平衡树。
